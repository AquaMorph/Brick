# Commits

## Commit Message Format

Follow conventional commits style (all lowercase).
- `feat(scope): description` - New feature
- `fix(scope): description` - Bug fix
- `refactor(scope): description` - Code refactoring
- `docs(scope): description` - Documentation changes
- Example: `feat(ui): customizable sidebar` or `fix(capture): reduce image capture time`

## Commit Content

Commit messages should describe at a high level what the change accomplishes. Never reference what files are changed. This is tracked by git and is useless information. Avoid using words like add, changed, or other obviously useless filler words. If the commit is particularly complicated it's fine to add detail to the commit message rather than just filling a title but this should be rare.

Never put a coauthor by an AI assistant like claude or codex. All AI activity is the responsibility of the human and I expect you to take complete ownership of all AI driven development.
